# completeness-gate — 完整性门禁

> 知识库加载后的强制交叉验证步骤。读完规范不算完，必须逐条对照目标代码。

---

## 触发时机

P2 方案设计阶段（production.md [P2b]），知识库加载完毕后，对每个将被修改的目标文件执行。

## 流程

```
知识库规范（knowledge.md 加载的 ShaderStructure / ScriptStructure 等）
        │
        ▼
  目标代码（将被修改的文件）
        │
        ▼
  ┌─────────────────────────────────────────────┐
  │         规范符合度检查清单                    │
  │                                             │
  │  § 规范条目             状态    说明          │
  │  ─────────────────────────────────────────  │
  │  §3① 文件头注释格式      ✅     已符合        │
  │  §3③ 复杂计算独立函数    ❌     Frag 150行     │
  │  §7  禁止函数内逐行注释  ❌     10+ 条 // ──   │
  │  §5  Pass 函数命名规范   —     不适用         │
  │  ...                                        │
  └─────────────────────────────────────────────┘
        │
        ▼
  所有 ❌ 条目 → 自动进入 P2c 修改计划
```

## 输出格式

在方案设计中显式输出检查清单：

```markdown
### 规范符合度检查 — PCSS.shader

| 规范条目 | 状态 | 当前代码 | 修改计划 |
|---------|------|---------|---------|
| ShaderStructure §3③ 功能解耦 | ❌ | Frag 150行单函数 | 按 // ── 段拆分为独立函数 |
| ShaderStructure §7 禁止内联注释 | ❌ | 10+ 条 // ── Section ── | 移除注释，函数名替代分段标记 |
| ShaderStructure §1 文件头注释 | ✅ | 已有 | — |
| ... | | | |
```

## Rationalizations

| Agent 可能的借口 | 为什么不能跳过 |
|-----------------|--------------|
| "规范大致看了一下，心里有数" | 不逐条对照一定会遗漏。必须显式输出每条的符合状态。 |
| "目标文件太复杂，先改再说" | 复杂文件更需要先对照规范，否则改完才发现不符合。 |
| "有些规范条目我不确定是否适用" | 标记为 `—` 并附原因，不要跳过。 |
| "参考实现没读，我根据规范推断就够了" | 规范是抽象描述，参考实现是具体范例。缺少参考会导致"我以为理解了但其实没理解"。 |
